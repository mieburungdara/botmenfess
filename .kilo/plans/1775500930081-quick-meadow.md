# Menfess Workflow Plan (Telegram Bot Implementation)

## Overview
This plan outlines the workflow for a Telegram-based menfess (anonymous confession) system where users send messages to a bot, which then forwards approved content to a designated Telegram channel.

## Core Components

### 1. Submission System (Telegram Bot)
- Users send anonymous messages/confessions to the Telegram bot via private chat
- Submission method:
  - Direct messages to the bot (users initiate chat with @yourmenfessbot)
- Anonymity is preserved - bot does not reveal user IDs or usernames to channel admins
- Bot must be set to privacy mode disabled to receive all messages (or use commands)

### 2. Message Processing (Telegram Bot)
- Bot receives submissions via private messages from users
- Screening process (can be automated or manual):
  - Content review for appropriateness (text analysis, keyword filtering)
  - Filtering of spam, hate speech, or harmful content
  - Duplicate removal (optional)
  - Categorization (if applicable, e.g., by topic)
- Selection of messages to publish:
  - Manual approval by admin/operator (recommended for quality control)
  - OR automatic publishing with post-moderation (riskier)
  - Bot can queue messages for review

### 3. Publication Process (Telegram Channel)
- Approved messages are forwarded/posted to the designated Telegram menfess channel
- Posts maintain anonymity - no user identifiers revealed (bot hides sender info)
- Typical post format:
  - Confession/message content
  - Optional hashtags (#menfess, #confession, etc.)
  - Optional numbering or labeling for tracking (e.g., "Menfess #123")
  - Timestamp of posting (not submission)
  - Bot can add footer like "Dikirim secara anonim via @yourmenfessbot"
- Publishing methods:
  - Bot automatically forwards approved messages to channel
  - OR bot notifies admin for manual posting (less common)

### 4. Engagement Phase (Telegram Channel)
- Followers can interact with published menfess posts in the Telegram channel:
  - Reactions (emoji reactions to posts)
  - Comments/replies (if comments are enabled on the channel)
  - Polls (bot can create polls in the channel)
  - Views counter (Telegram shows view counts)
- Operator may engage by:
  - Posting follow-up messages or clarifications
  - Creating discussion threads (replying to menfess posts)
  - Running polls related to menfess topics
  - Sharing related menfess posts (if relevant)
- Note: Telegram channels are primarily broadcast-medium; engagement is more limited than Twitter

### 5. Moderation & Guidelines (Telegram)
- Community guidelines for submissions:
  - Prohibited content: harassment, hate speech, illegal activities, NSFW (unless in designated NSFW channel)
  - Encouraged content: personal stories, opinions, questions, light-hearted confessions
- Reporting mechanism for inappropriate published content:
  - Users can report to admin via private message to bot or admin account
  - Bot can forward reports to admin for review
- Operator discretion in what gets published (via approval queue)
- Regular cleanup/archive of old posts:
  - Bot can automatically delete posts after X days (if desired)
  - OR manual archiving by admin
  - Telegram channels don't have built-in archive, so manual deletion or bot-based scheduling needed

### 6. Technical Implementation Considerations (Telegram Bot)
- Technology Stack:
  - PHP (7.4 or higher) for bot logic
  - MySQL with InnoDB engine for data storage
  - Telegram Bot API for platform integration
- Telegram Bot API requirements:
  - Create bot via @BotFather and get API token
  - Set privacy mode: disabled (to receive all messages) OR use commands like /start, /menfess
  - Add bot as admin to target channel with posting rights
- Submission collection:
  - Bot receives messages via Telegram Bot API (getUpdates or webhook)
  - Extract message text and ignore sender info for anonymity
  - Store submissions in MySQL database with InnoDB engine
  - Tables needed: submissions (id, message_text, timestamp, status, moderator_notes), channel_posts (id, submission_id, telegram_message_id, post_timestamp)
- Content moderation:
  - Automated: keyword filtering, regex patterns for prohibited content (implemented in Node.js)
  - Manual: admin approval queue via bot interface (Node.js commands)
  - Hybrid: auto-filter obvious spam, manual review for gray areas
- Publication system:
  - Bot uses sendMessage or forwardMessage API (via php-telegram-bot or similar library) to post to channel
  - Option to schedule posts for consistent timing (using cron jobs or Laravel scheduler)
  - Rate limiting to avoid Telegram API limits (implemented in PHP)
- Additional features:
  - User feedback: acknowledgment when submission received (via bot message)
  - Admin commands: /approve, /reject, /queue, /stats (implemented with php-telegram-bot or similar library)
  - Analytics: track submissions, approvals, posts, engagement (MySQL queries)
  - Multi-language support if needed (i18n in PHP)
  - Error handling and logging (Monolog or similar for PHP)
- Database Design (MySQL InnoDB):
  - submissions table: id (PK, auto_increment), message_text (TEXT), submitted_at (TIMESTAMP), status (ENUM: 'pending', 'approved', 'rejected'), moderator_notes (TEXT, nullable), reviewed_at (TIMESTAMP, nullable), reviewed_by (VARCHAR, nullable)
  - channel_posts table: id (PK, auto_increment), submission_id (FK to submissions.id), telegram_message_id (BIGINT), posted_at (TIMESTAMP)
  - Use InnoDB for foreign key support and transaction safety
  - Consider indexes on status, submitted_at for performance
- Manual systems: operator manually copies/pastes from bot DMs to channel (not recommended)

## Workflow Summary (Telegram Implementation with PHP & MySQL)
1. User → Sends anonymous message to Telegram bot via private chat
2. Bot (PHP) → Receives message via Telegram API, stores in MySQL InnoDB submissions table (status: 'pending')
3. Bot → Optionally sends acknowledgment to user: "Pesan diterima, sedang dalam proses review"
4. Operator/Admin → Reviews submission via bot commands (e.g., /queue shows pending submissions)
5. Operator → Uses bot commands to approve (/approve [id]) or reject (/reject [id]) submission
6. Bot (PHP) → Updates submission status in MySQL, if approved: posts to Telegram channel using sendMessage API
7. Bot → Stores telegram_message_id in MySQL channel_posts table for tracking
8. Audience → Views and engages with post in Telegram channel (reactions, comments if enabled, views)
9. Operator → Manages engagement, handles reports (via /report command), maintains community standards
10. System → Periodic cleanup tasks (PHP cron jobs or Laravel scheduler) can remove old posts based on retention policy

## Variations (Telegram)
- Themed menfess (specific topics like relationships, school, work) - separate bots/channels or topic tags
- Timed menfess (submissions open only during certain hours) - bot enables/disables submission based on time
- Collaborative menfess (multiple operators) - multiple admins can approve via bot interface
- Integrated menfess (feature within larger accounts) - bot responds to mentions or commands in group chats
- Channel vs Group: menfess works best as a channel (broadcast) but can work in groups with admin oversight
- Multiple channels: separate channels for different content types (e.g., SFW vs NSFW, different topics)

## Best Practices (Telegram Bot with PHP & MySQL)
- Clear communication: Set bot description/commands to explain how to submit menfess
- Welcome message: Bot sends greeting with instructions when users start chat
- Submission guidelines: Pin message in bot chat or channel about what's allowed
- Consistent posting schedule: Use bot to queue and schedule posts for peak engagement times (cron jobs or Laravel scheduler)
- Transparency: Occasionally share stats from MySQL (e.g., "Received 50 submissions today, posted 10")
- Protection of anonymity: Never log or store user IDs with submissions; use MySQL to store only message text
- Database best practices:
  - Use MySQL InnoDB for ACID compliance and foreign key support
  - Implement proper indexing on submissions table (status, submitted_at)
  - Use connection pooling for MySQL connections
  - Regular database backups
  - Consider archiving old submissions/posts to separate tables
- Anti-spam measures: Rate limiting per user (implement in PHP with Redis or memory store), CAPTCHA for suspicious activity (if needed)
- Moderation transparency: Let users know why submissions were rejected (if appropriate, store notes in MySQL)
- Community building: Occasionally post themed menfess or ask for topic suggestions
- Technical reliability:
  - Implement comprehensive error handling in PHP (try/catch, exception handling)
  - Use logging library (Monolog or similar) for both application and database errors
  - Implement retry logic for Telegram API calls
  - Backup submission queue (MySQL transactions ensure data isn't lost)
  - Health check endpoints for monitoring
- Legal compliance: Be aware of local laws regarding anonymous communication and content (consult legal advisor)
- User experience: Fast acknowledgment of submissions, clear status updates, informative error messages
- Development practices:
  - Use environment variables for configuration (token, DB credentials)
  - Implement proper logging without sensitive data
  - Consider using a PHP framework (Laravel, Symfony) for better maintainability
  - Write unit tests for critical functions (using PHPUnit)
  - Use Composer for dependency management
